# Research Submission Readiness

## Overview

Prepare research work for venue-specific submission by checking content integrity, formatting, reproducibility, and likely reviewer concerns.

## When to Use

- The user is preparing to submit a paper
- A target venue or deadline is set
- Reviews have arrived and rebuttal is needed
- Camera-ready or revision materials are being prepared

## Workflow

1. Check venue fit: scope, novelty expectations, paper length/template, anonymity, data/code policy, ethics and reproducibility requirements.
2. Run integrity check: real citations, no invented results, tables match logs, claims match evidence, limitations present, baselines and datasets accurate.
3. Check package: PDF, supplement, references/BibTeX, code/data statement, checklist, figures/tables, anonymous version.
4. For rebuttal, split comments by reviewer, classify issues, group duplicates, mark answer type, draft concise responses, and list edits or experiments needed.
5. Give readiness decision: Ready, Ready after minor fixes, Major fixes required, or Not ready.

## Common Rationalizations

| Rationalization | Reality |
|---|---|
| “This is obvious.” | Obvious research decisions still need artifacts and acceptance criteria. |
| “We can fill evidence later.” | Evidence changes the claim boundary; defer it only when labeled provisional. |
| “The user wants confidence.” | The user needs useful truth. Surface risks and tradeoffs. |
| “This step slows us down.” | A small gate now prevents expensive rework later. |

## Red Flags

- Confident claims without evidence
- No artifact created or updated
- Missing next action
- Scope expands beyond the user’s request
- Weaknesses hidden instead of tracked
- Decisions not traceable to literature, experiments, code, or logs

## Verification

- [ ] The active artifact is named
- [ ] Known facts, hypotheses, and plans are separated
- [ ] Assumptions are surfaced when needed
- [ ] Evidence gaps are labeled
- [ ] Next action is concrete and small
